# 词缀获取与映射逻辑

> 目标：从内存读取魔法/稀有/手工物品的词缀 id，并映射为词缀名（英文/中文）与词条（属性）。
> 适用范围：暗黑2原版 1.13c（D2Loader.exe + anhei2mapBUS mod，-locale kor），只读不写不注入。
> 更新日期：2026-09-11

---

## 1. 词缀槽位布局（物品结构内）

每个物品的 ItemData（idat）中，**连续 6 个 WORD** 存放词缀 id：

```
idat + 0x38  槽0（前缀1）
idat + 0x3A  槽1（前缀2）
idat + 0x3C  槽2（前缀3）
idat + 0x3E  槽3（后缀1）
idat + 0x40  槽4（后缀2）
idat + 0x42  槽5（后缀3）
```

- **布局规则：3 前 3 后**。槽0-2 = 前缀（prefix），槽3-5 = 后缀（suffix）。
- 值为 0 = 该槽无词缀（空）。实际词条数 = 非零槽数。
- 验证实例（三条项链）：
  - 项链1：`985 1312 1051 | 742` = 3前1后，4 词条
  - 项链2：`1326 1055 1121 | 117 374` = 3前2后，5 词条
  - 项链3：`1055 0 0 | 744 118 363` = 1前3后，4 词条

### 物品遍历链路（找 idat）

```
pInv      = *[D2Client+0x11B800 + 0x60]
pFirstItem= *[pInv + 0x0C]              ; 第一件物品
cur       = pFirstItem                  ; unit 结构（物品单元）
循环:
  txt     = word[cur + 0x04]            ; 物品码（520=项链 amu / 522=戒指 rin）
  idat    = *[cur + 0x14]               ; ItemData 结构
  词缀槽  = idat + 0x38 起 6 WORD
  next    = *[idat + 0x64]              ; 下一件物品
```

## 2. 词缀 id → 词缀实体（核心映射）

**id = 扩展表行号**（重要修正：早期误用"id=行号+2"，全错，已废弃）。

- 扩展表（词缀总表，prefix/suffix 混排）：
  - 表地址：`[D2Common + 0x9FBBC]`（会话实测 0x1244DFCC，重启后现取）
  - 行数：`[D2Common + 0x9FBB8]`（会话实测 1452）
  - 行宽：`0x90` 字节
  - 行首：name（ASCII，`\0` 结尾）
- **词缀 id = 行号**（0-1451 有效；id 0 通常不用于物品槽）
- 验证锚点（用户实测权威）：
  - 行 985 = `Iron`（铁之）= 准确率 att
  - 行 1312 = `Monk's`（僧人之）= 圣骑士技能 pal
  - 行 1051 = `Snake's`（蛇之）= 法力 mana
  - 行 742 = `of the Locust`（蝗虫的）= 生命偷取 lifesteal

### 行内结构（关键字段，0x90 行宽内）

| 偏移 | 字段 | 说明 |
|---|---|---|
| +0x00 | name | 词缀英文名，`\0` 结尾（"of " 开头 = 后缀，否则前缀） |
| +0x2C | mod min | 词条数值下限（官方值） |
| +0x30 | mod max | 词条数值上限（官方值） |
| +0x58 | stat id | 属性编号（如 110=att 区） |

> 注：+0x2C/+0x30 为**官方 txt 数值**；anhei mod 实际运行值不同（见 §5 限制）。

## 3. 中文名获取（名池）

词缀中文名在 tbl 全量字符串池中，UTF-8 `英文\0中文\0` 交错存储：

- 会话地址：`0x12801ACC` 起（tbl 全量池，含词缀名/套装名/暗金名/怪物名/UI 文本）
- anhei 前缀池：`0x12804000` 区（如 BloodUM→鲜血之）
- 原版前缀池：`0x127FEAC5`（如 Emerald→祖母绿之）
- 后缀池：`0x1345118A`（如 of Inertia→惯性的）

扫描方式：按 `ASCII字符串\0 中文字符串\0` 模式解析，建立 `en -> zh` 字典。
注意：该池是 tbl 全量池，非词缀专用，命中需按词缀名精确匹配。

## 4. 词条（mod 属性）参考——txt 模板

`G:\game\diablo 2\tool\bin2txt\template\MagicPrefix.txt`（671 行）/ `MagicSuffix.txt`（749 行）提供属性列：

```
列: name(0) spawnable(1) rare(2) level(3) maxlevel(4) levelreq(5)
    frequency(6) group(7) mod1code(13) mod1param(14) mod1min(15) mod1max(16)
    mod2code(17)... mod3code(21)... itype1(25)... etype1(32)...
```

- 同名词缀在 txt 有**多行变体**（不同 level/itype/数值档），合并为 variants 列表。
- 常见 mod code → 中文词条映射：
  - att=准确率、pal=圣骑士技能、sor=法师技能、bar=野蛮人技能、dru=德鲁伊技能、asn=刺客技能、nec=死灵法师技能、ama=亚马逊技能
  - mana=法力、manasteal=法力偷取、lifesteal=生命偷取、str=力量、dex=敏捷、vit=活力、ene=能量
  - res-fire=火焰抗性、res-cold=冰冷抗性、res-ltng=闪电抗性、res-pois=毒素抗性
  - red-dmg=伤害减少、red-mag=魔法伤害减少、light=照亮范围、life=生命

## 5. 已知限制（重要）

1. **具体数值（roll 值）不可从物品内存读取**：
   - 实测扫描 idat/cur ±0x400 无具体数值（如项链1 的 2/19/2/4 不存在物品结构中）
   - 词缀槽 +0x44 起全 0，不存储实例化数值
   - 蓝装词缀数值由 mod 运行时计算（GetItemMagicalMods 在 1.13c 进程全 0 不可用）
2. **txt/扩展表行 = 官方数值，与 mod 实际值不同**：
   - 官方：Iron att 21-40、Monk's pal 1-1、Snake's mana 5-10、of the Locust lifesteal 4-5
   - mod 实际（用户从游戏内确认）：准确率 10-30、圣骑士技能 1-2、法力 1-90、生命偷取 2-6
   - 原因：anhei mod 运行时覆盖了词缀数值；mpq 内 txt 解析被禁止，无法读取 mod 权威表
3. **"鲜血之/螺旋"类词条**：属物品特殊名（tbl 侧），不在词缀 id 槽内，需另查。

## 6. 映射产物

`temp\dict_magic_affixes.json`（1414 条，id 0-1451，统一表，替代早期分拆的 prefix/suffix 两表）：

```json
{
  "985": {
    "row": 985,
    "name": "Iron",
    "name_zh": "铁之",
    "type": "P",
    "mod": [
      {"zh": "准确率", "code": "att", "range": "21-40", "param": "0"},
      {"zh": "准确率", "code": "att", "range": "13-24"}
    ]
  }
}
```

- `type`：P=前缀（name 非 "of " 开头）、S=后缀
- `mod`：词条列表（官方 txt 多档），zh 为词条中文、code 为 mod code、range 为官方数值档
- 旧文件 `dict_magic_prefix.json` / `dict_magic_suffix.json`（id=行号+2 版）已废弃

    if not iid:

    typ = "S" if name.startswith("of ") else "P"
